----------------------------------------------------------------------

CDI-Telopperは、複数の外部配信サービスから防災情報を受信し、OBS Studioで
使用できる字幕と任意の通知音を生成するWindowsアプリケーションです。

本ソフトウェアはベータ版です。気象庁、自治体、受信プロバイダー、通信回線、
Windows、OBS Studio、配信サービスなどの状態により、情報の遅延、欠落、重複、
順序の前後、誤表示、接続切断、音声の不発、表示の中断が発生する可能性があります。

本ソフトウェアは、気象庁、自治体、放送機関その他の公的機関が提供する公式情報、
避難情報、避難判断を代替するものではありません。実際の災害時は、必ず複数の
公式情報を併用してください。CDI-Telopperだけを根拠に避難、放送、配信その他の
重要な判断を絶対に行わないでください。

初めて本番運用する前、および設定・OBS・音源・受信元を変更した後は、必ず
Sandbox、収録シナリオ、履歴リハーサル、生データ・テストライブラリーを利用し、
字幕、ページ送り、取消・解除、音声、OBS出力、配信画面上の配置を確認してください。

AXISおよびDMDATA.JPは、利用者自身のアカウント、契約、権限、認証情報が必要です。
利用条件、再配信条件、契約区分、同時接続数、利用可能な電文を各提供元で確認して
ください。認証情報を第三者へ渡したり、配布物や公開リポジトリへ含めたりしないで
ください。

1. CDI-Telopperの概要
----------------------------------------------------------------------

1.1 目的

CDI-Telopperは、地震、津波、緊急地震速報、気象警報・注意報、火山情報、
南海トラフ地震臨時情報などを受信し、配信者がOBS Studioへ字幕として表示する
ためのソフトウェアです。

受信した電文は共通の内部形式へ変換され、表示フィルター、更新・取消判定、
重複排除、ページ生成、表示優先度、音声条件を通過した後、OBS Local Viewへ
送出されます。

1.2 主な機能

・P2P地震情報 API、DMDATA.JP、AXIS、Wolfxへの対応
・情報種別ごとに受信元を個別選択
・選択された情報が1件もないAPIには接続しない接続制御
・緊急地震速報、地震、津波、気象、火山、南海トラフ情報の字幕生成
・用途別OBSブラウザーソース出力
・地震、津波、気象、EEWの任意音声出力
・受信電文と過去電文の独立ウインドウ表示
・過去電文の訓練再表示
・P2P履歴、NII気象庁防災情報XML DB、外部XMLの履歴リハーサル
・収録シナリオと生データ・テストライブラリー
・電文更新、取消、解除、重複、優先度、複数ページの処理
・OBS WebSocket v5によるブラウザーソースの自動作成・URL更新
・AXISアクセストークンの期限監視と条件付き自動更新
・ログ、任意の生データ保存、診断情報ZIP出力
・設定プロファイル、本番前セルフチェック、異常監視の基盤

1.3 出力先

同一PC上のOBS向けに、次の4つのブラウザーソースを独立して出力します。

・CDI-Telopper 地震字幕・全ての音声
・CDI-Telopper 緊急地震速報
・CDI-Telopper 津波字幕
・CDI-Telopper 気象情報

地震、火山、南海トラフなどの一般字幕と、すべての通知音は
「地震字幕・全ての音声」へ送出されます。EEW、津波、気象は表示の競合を避ける
ため専用字幕URLを持ちます。

OBSの音声ミキサーへ追加されるのは「地震字幕・全ての音声」だけです。
緊急地震速報、津波字幕、気象情報の各ソースは映像専用として扱われます。

1.4 ベータ版について

2.0.0-beta系は、複数プロバイダー、気象、火山、分類別ルーティング、履歴XML、
電文確認などを検証する開発版です。1.x安定版とは設定保存系列を分離しています。
本番配信へ投入する前に、利用者の環境で長時間動作、再接続、OBS再起動、音声、
取消・解除、Windows再起動を含む確認を行ってください。

3. 対応する情報種別と電文
----------------------------------------------------------------------

3.1 緊急地震速報（EEW）

・P2P地震情報 APIの緊急地震速報
・DMDATA.JP警報契約のVXSE43、およびその取消
・DMDATA.JP予報契約のVXSE45のうち警報を含む電文、およびその取消
・AXIS専用eewチャンネルの警報、続報、取消
・AXIS/DMDATA.JP経由の対応する気象庁XML

警報を含まない予報だけの電文は、運用上の誤表示を避けるため表示対象外になる場合が
あります。異なるイベントIDのEEWは最大2件を同時表示できます。同一イベントの
続報は既存表示を更新し、取消報は対象イベントの表示だけを取消へ切り替えます。

3.2 地震情報

主な対応電文は次のとおりです。

・VXSE51 : 震度速報
・VXSE52 : 震源に関する情報
・VXSE53 : 震源・震度に関する情報
・VXSE62 : 長周期地震動に関する観測情報
・VYSE60 : 北海道・三陸沖後発地震注意情報
・P2P地震情報 APIの地震情報

震度速報では、観測された地域をページ分割して表示します。震源・震度情報では、
震源、規模、最大震度、地点情報を電文の内容に応じて表示します。取消電文は、
過去の震度・震源をそのまま残さず、取消であることが分かる字幕へ切り替えます。

3.3 津波情報

・VTSE41 : 津波警報・注意報・予報、および更新・解除
・VTSE51 : 津波情報
・VTSE52 : 沖合の津波観測に関する情報
・P2P地震情報 APIの津波情報

大津波警報、津波警報、津波注意報、津波予報を区分し、重要度の高い順にページを
生成します。津波予報（若干の海面変動）は既定で字幕非表示です。解除電文では、
継続中の警報区分を残さず、解除されたことを表示します。

3.4 気象情報

2026年体系の主な対応電文は次のとおりです。

・VPWW55 : 大雨
・VPWW56 : 土砂災害
・VPWW57 : 高潮
・VPWW58 : 暴風・暴風雪
・VPWW59 : 波浪
・VPWW60 : 大雪
・VPWW61 : その他の注意報
・VPOA50 : 記録的短時間大雨情報
・VPBS50 : 府県気象防災速報
・VPBS51 : 府県気象防災速報（潮位）
・VPHW50 : 竜巻注意情報
・VPHW51 : 目撃情報を含む竜巻注意情報

移行検証用として旧体系VPWW53、VPWW54も選択できます。旧体系と2026年体系は
重複した状態を表すため、同時に要求しません。VPWS50は正規化可能ですが、個別電文
との重複表示を避けるため、通常の受信要求には含めません。

気象情報は、特別警報、警報、記録的短時間大雨情報、気象防災速報、竜巻注意情報、
その他の注意報を個別に表示設定できます。対象地域は全国または複数都道府県を
指定できます。

3.5 火山情報

・VFVO50 : 噴火警報・予報
・VFVO56 : 噴火速報

火山名、噴火警戒レベル、警報区分、対象地域、発表・引上げ・引下げ・解除・取消、
活動状況、防災上の警戒事項など、電文に含まれる情報を字幕へ構成します。

3.6 南海トラフ地震臨時情報

・VYSE50 : 南海トラフ地震臨時情報

見出し、キーワード、調査中・巨大地震注意・巨大地震警戒・調査終了など、電文に
含まれる区分を表示します。受信元は他の地震情報とは別に選択できます。

3.7 対応外または表示対象外の電文

接続先が配送するすべての電文を字幕化するわけではありません。対応外電文、
警報条件を満たさないEEW、選択外プロバイダーの電文、表示フィルターで除外された
項目、破損データ、重複報、古い更新報などは表示されません。受信結果やログだけが
更新される場合があります。


4. 受信プロバイダーと分類別ルーティング
----------------------------------------------------------------------

4.1 情報種別ごとの選択

次の6分類ごとに受信元を設定します。

・EEW
・地震情報
・津波情報
・気象情報
・火山情報
・南海トラフ

選択肢は、その分類で使用可能な「P2P」「AXIS」「DMDATA.JP」「Wolfx」
「受信しない」です。WolfxはEEWと地震情報だけで選択できます。
気象、火山、南海トラフなど、P2Pで扱わない分類にはP2Pを選択できません。

複数のプロバイダーが選ばれている場合、CDI-Telopperは必要なAPIへ同時接続します。
例として、地震・津波をP2P、EEW・気象・火山・南海トラフをAXISに設定した場合は、
P2PとAXISへ接続します。選択外プロバイダーから同種の電文が届いても、正規化後に
除外します。

すべての分類で特定プロバイダーが未選択なら、そのプロバイダーのAPIには接続しません。
不要な電文を止めたい場合は、表示フィルターだけでなく、受信元を「受信しない」に
設定してください。

4.2 P2P地震情報 API

P2Pは主にEEW、地震情報、津波情報で利用します。

Production WebSocket : wss://api.p2pquake.net/v2/ws
Production REST       : https://api.p2pquake.net/v2

Sandboxは専用WebSocketへ接続し、概ね約30秒間隔で試験データを受信します。
554、555、561、9611など、CDI-Telopperの字幕対象外コードでは受信結果とログだけが
更新されます。

P2P地震情報 APIは気象庁が運営する公式APIではありません。気象庁発表情報を扱う
外部サービスとして公式情報と併用し、提供元の利用条件、レート制限、二次利用条件を
確認してください。

4.3 DMDATA.JP

DMDATA.JPは契約者向けのプロバイダーです。利用する分類が契約区分に含まれていること、
必要なAPI権限とWebSocket接続枠があることを確認してください。

API Base URLの既定値は次のとおりです。

  https://api.dmdata.jp/v2

認証情報は設定画面へ入力します。現在の実装ではAPIキーを使用します。保存時には
Windows DPAPI CurrentUserで暗号化し、平文をsettings.jsonへ保存しません。
別のWindows利用者や別PCへsettings.jsonだけをコピーしても復号できません。

「試験電文を受信」を有効にすると、提供元が試験扱いとして配送する電文も受信対象に
含めます。本番運用時は意図を確認して設定してください。

受信分類から、地震・津波、気象、火山の必要区分と電文型を自動設定します。
EEWはDMDATA.JPの契約に合わせ、警報契約（eew.warning/VXSE43）または予報契約
（eew.forecast/VXSE45）を選択します。両区分は別契約のため、選択した一方だけを
Socket Startへ指定します。予報契約では、VXSE45のうち警報を含む電文と取消だけを
字幕対象とし、予報だけの電文は表示しません。

契約にない分類を選ぶと認証・契約エラーになります。401、402、403などの
資格・契約エラーは、無限再接続を避けるため接続エラーとして扱う場合があります。

4.4 AXIS

AXISは試験的プロバイダーです。利用者自身が正規登録したアクセストークンを使用し、
現在の利用条件、配信条件、チャンネル提供状況を確認してください。

API Base URLの既定値は次のとおりです。

  https://axis.prioris.jp/api/

使用するチャンネルは選択した分類から自動構成します。

・eew              : AXIS専用EEW JSON
・jmx-seismology   : 地震・津波・南海トラフ関連の気象庁電文
・jmx-meteorology  : 気象関連の気象庁電文
・jmx-volcanology  : 火山関連の気象庁電文

アクセストークンはWindows DPAPI CurrentUserで暗号化保存します。トークン値をログや
診断ZIPへ平文で出力しない設計です。

4.5 AXISトークン自動更新

CDI-TelopperはJWTの有効期限を端末内で確認します。

・起動時に1回確認
・起動中は1日1回確認
・有効期限の残りが7日未満の場合だけ更新APIを呼び出す
・更新成功後は新しいトークンを直ちに暗号化保存
・受信中の場合はAXIS接続だけを更新されたトークンで再接続
・トークン値はログへ記録しない

すでに期限切れのトークンは更新できません。期限切れ、認証失敗、契約期限切れが
表示された場合は、AXIS側で有効なトークンを発行し直して保存してください。

4.6 Wolfx

Wolfxは認証不要の公開WebSocket APIです。EEWと地震情報の受信元として選べます。

  EEW WebSocket      : wss://ws-api.wolfx.jp/jma_eew
  地震情報WebSocket  : wss://ws-api.wolfx.jp/jma_eqlist

EEWは警報と取消を字幕対象とし、予報だけの更新は表示しません。

重要：Wolfxの地震情報は、現在はVXSE53相当の「震源・震度情報」のみです。
震度速報（VXSE51）、震源に関する情報（VXSE52）、長周期地震動に関する観測情報
（VXSE62）などはWolfxから取得できません。これらが必要な運用ではP2P、DMDATA.JP、
AXISなど、必要な情報を配信する別の受信元を選択してください。

Wolfxの地震情報は一覧更新の最新項目を取り込み、イベントIDと署名による重複判定を
行います。一方の分類だけをWolfxへ割り当てた場合は、もう一方のWebSocketへ接続
しません。heartbeatにはpingを
返し、切断時は自動再接続します。

Wolfx APIは政府機関・気象機関が運営する公式APIではありません。気象庁などの
公式情報と併用し、提供元の最新仕様、規約、接続制限を確認してください。

4.7 推奨構成例

利用可能な契約を確認したうえで、次のように分類できます。

  EEW          : AXIS、DMDATA.JP、P2P、またはWolfx
  地震情報     : P2P、DMDATA.JP、AXIS、またはWolfx
  津波情報     : P2P、DMDATA.JP、またはAXIS
  気象情報     : AXISまたはDMDATA.JP
  火山情報     : AXISまたはDMDATA.JP
  南海トラフ   : AXISまたはDMDATA.JP

契約がない分類、配信に使用しない分類は「受信しない」を選択してください。


5. 動作環境と配布形式
----------------------------------------------------------------------

5.1 動作環境

・Windows 10またはWindows 11（64ビット）
・OBS Studio 28以降を推奨
・使用する受信プロバイダーへ接続可能なインターネット環境
・AXIS/DMDATA.JP利用時は有効な契約と認証情報
・音声利用時はOBSのブラウザーソース音声を扱える環境
・Windowsの時刻が正しく同期されていること

配布パッケージは.NET 8自己完結型です。通常利用ではVisual Studioや.NET SDKを
インストールする必要はありません。

5.2 配布形式

［フォルダ版］

実行ファイルと必要ファイルをフォルダへ展開した形式です。ファイル数は多いですが、
起動時の展開負荷を抑えやすく、問題調査にも向きます。

［シングルファイル版］

主な実行内容をCDI-Telopper.exeへまとめた形式です。配布と保管が簡単ですが、
初回起動やセキュリティソフトの検査に時間がかかる場合があります。

5.3 配布物の完全性

配布ZIPとCDI-Telopper.exeは、可能であればSHA256SUMS.txtのハッシュと照合して
ください。ZIP内から直接実行せず、通常の書き込み可能なフォルダへ展開してください。


6. インストール、初回起動、更新
----------------------------------------------------------------------

6.1 新規インストール

1) 配布ZIPをダウンロードする
2) ZIPを右クリックし、必要に応じてプロパティのブロック解除を行う
3) 任意の通常フォルダへすべて展開する
4) CDI-Telopper.exeを起動する
5) Windowsやセキュリティソフトの確認が出た場合は、配布元とハッシュを確認する
6) 操作画面で受信元、OBS、音声を設定する

Program Filesなど、一般利用者が書き込みにくい場所へ無理に配置する必要はありません。
設定とログは実行フォルダではなく、既定ではユーザー別アプリデータへ保存されます。

6.2 更新

1) CDI-Telopperをタスクトレイから完全終了する
2) 設定フォルダをバックアップする
3) 新版ZIPを新しいフォルダへ展開する
4) 旧版フォルダへ上書きせず、新版のCDI-Telopper.exeを起動する
5) 設定移行ログと受信元を確認する
6) OBS自動同期またはURL貼り直しを行う
7) テストを実行してから本番接続する

2.0.0-beta系の設定は同じ保存系列を使用します。旧設定を読み込んだ場合、設定スキーマを
現行形式へ移行して保存することがあります。更新前バックアップを推奨します。

6.3 ウイルス対策ソフトについて

自己完結型・シングルファイルの実行ファイルは、初回起動時に検査が長引くことが
あります。除外設定を行う場合は、プロジェクトやドキュメントをまとめた広い親フォルダ
ではなく、配布物専用フォルダへ範囲を限定する方が安全です。除外フォルダへ第三者から
入手した実行ファイルを無条件に置かないでください。


7. 起動、最小化、タスクトレイ、終了
----------------------------------------------------------------------

7.1 起動

CDI-Telopper.exeをダブルクリックします。多重起動は抑止され、既存の操作画面を
前面へ戻します。起動しただけでは外部受信を自動開始しません。設定を確認してから
「接続」を押してください。

OBS Local Viewが有効なら、同一PC内のローカル出力サーバーを開始します。

7.2 操作画面右上の「×」

「×」を押してもアプリは終了しません。操作画面をタスクトレイへ格納し、受信、
OBS出力、再接続、トークン期限監視を継続します。初回はバックグラウンド動作を
知らせる通知が表示されます。

7.3 タスクトレイ

タスクトレイアイコンの操作は次のとおりです。

・ダブルクリック                     : 操作画面を開く
・右クリック「CDI-Telopperを開く」   : 操作画面を開く
・右クリック「受信・過去電文を確認」 : 電文確認ウインドウを開く
・右クリック「終了」                 : 受信とローカル出力を停止して完全終了

7.4 独立ウインドウ

「受信・過去電文を確認」ウインドウは操作画面から独立しています。操作画面を最小化、
非表示、タスクトレイ格納しても、確認ウインドウはそのまま表示されます。

7.5 完全終了

タスクトレイアイコンを右クリックし「終了」を選択してください。Windowsの終了や
サインアウト時にも後処理を行います。タスクマネージャーからの強制終了は、状態保存、
DMDATA Socket Close、ログのフラッシュが行われない可能性があるため常用しないで
ください。


8. 初回設定の推奨手順
----------------------------------------------------------------------

1) 使用する受信プロバイダーの契約と認証情報を準備する
2) 「受信・フィルター」で6分類の受信元を選択する
3) 不要な分類は「受信しない」にする
4) P2Pを使う場合、最初はSandboxを選択する
5) DMDATA.JPまたはAXISを使う場合、API URLと認証情報を入力する
6) 表示対象の種別、地域、警報レベルを選ぶ
7) 「表示・出力」でページ時間、自動消去、背景、解像度を確認する
8) OBS Local ViewとOBS WebSocket自動登録を設定する
9) 「音声」で必要な音源だけを設定する
10) 画面右下の「保存して反映」を押す
11) OBSへ4つのブラウザーソースを登録または自動同期する
12) 「テスト」で各情報を表示する
13) OBSの映像、音声ミキサー、配信トラックを確認する
14) 取消、解除、複数ページ、同時EEWを確認する
15) 問題がなければProductionへ変更し「保存して反映」を押す
16) 「接続」を押す

設定値は「保存して反映」を押すまで確定しない項目があります。接続先に関係する設定を
受信中に保存した場合は、必要なプロバイダーを安全に再構成し、自動再接続します。


9. 操作画面の共通部分
----------------------------------------------------------------------

9.1 上部

・製品名と正式名称
・アプリケーションバージョン
・接続状態
・最終受信時刻
・「受信・過去電文を確認」ボタン

最終受信時刻は、字幕表示された時刻と同じとは限りません。表示対象外、重複、選択外、
破損などとして処理された電文でも更新される場合があります。

9.2 左側「接続」

［接続］
設定された受信元への接続を開始します。

［切断］
手動切断します。誤操作防止の確認画面が表示されます。手動切断後は利用者が再び
「接続」を押すまで受信を再開しません。

［状態］
未接続、接続中、接続済み、再接続待ち、切断中、認証エラーなどを表示します。

［再接続回数／次回再接続］
通信切断後の再試行状況を表示します。再接続は待ち時間を段階的に延ばし、複数端末が
一斉再接続しにくいよう揺らぎを加える場合があります。

［APIモード］
P2PのProductionまたはSandboxを表示します。

［受信結果］
直近の受信、採用、表示対象外、フィルター、重複、エラーなどの概要を表示します。

9.3 左側「出力」

［プレビューを表示］
PC上の確認用プレビューを開きます。これは廃止された常時オーバーレイではありません。
OBS出力と同じページ構成を確認するための操作用ウインドウです。

［表示中の字幕を編集］
現在表示中の字幕を配信者が確認し、必要な編集操作を行うための画面を開きます。
電文の原文そのものを書き換える機能ではありません。

［受信前の定型文を編集］
安定した識別子を持つ定型句を事前編集します。未知の項目は無視され、設定保存後の
新しいページ生成へ反映されます。

［種別別に表示を消去］
地震、津波、EEW、気象を個別に消去します。受信接続は継続します。消去後に新しい
対象電文を受信すれば、再び表示されます。

［OBS Local View］
ローカル出力サーバーの状態、ポート、接続クライアント数を表示します。

［用途別OBS URL］
地震字幕・全ての音声、緊急地震速報、津波字幕、気象情報のURLをコピーします。

9.4 「保存して反映」

編集した受信、表示、OBS、音声、履歴、安全設定を検証し、保存して実行中の機能へ
反映します。範囲外の値は補正またはエラー表示される場合があります。


10. 「受信・フィルター」タブ
----------------------------------------------------------------------

10.1 情報種別ごとの受信元

EEW、地震、津波、気象、火山、南海トラフの各行で受信元を選びます。

「受信しない」は、表示だけでなく取得自体を止めるための設定です。あるAPIを使う
分類が1件もなければ、そのAPIには接続しません。

10.2 P2P運用モード

［Production］
実際の配信APIへ接続します。

［Sandbox］
試験用接続先へ接続します。必ずしも全種類の字幕対象データが流れるわけではありません。

Custom接続先は一般配布UIでは使用しません。

10.3 DMDATA.JP設定

・API Base URL
・APIキー
・EEW契約区分（警報契約または予報契約）
・試験電文を受信
・旧体系VPWW53/54を使用

警報契約ではeew.warning/VXSE43、予報契約ではeew.forecast/VXSE45を要求します。
APIキーの実際の契約と異なる方を選ぶと、DMDATA.JPのSocket Startが契約エラーになります。
その他の契約区分と電文型は分類別選択から自動設定します。認証情報は保存時に暗号化されます。
APIキーを画面共有、スクリーンショット、ログ貼付けへ写さないでください。

10.4 AXIS設定

・API Base URL
・自動構成されたチャンネル
・アクセストークン
・旧体系VPWW53/54を使用

チャンネル欄は分類別選択に連動します。EEWをAXISに割り当てた場合はeewが含まれます。
トークンを変更して保存すると、必要に応じてAXIS接続を再構成します。

10.5 Wolfx設定

・EEW WebSocket URL
・地震情報 WebSocket URL

認証情報は不要です。通常は既定URLを変更しません。EEWまたは地震情報でWolfxを
選択した場合だけ該当するWebSocketへ接続します。

地震情報にWolfxを選択すると、設定画面に制限事項の警告を表示します。Wolfxで取得
できる地震情報は現在VXSE53相当の「震源・震度情報」のみです。VXSE51、VXSE52、
VXSE62などは取得できないため、必要な情報範囲を確認して受信元を選択してください。

10.6 表示フィルター

［緊急地震速報］
EEW字幕の表示を有効または無効にします。

［地震情報］
地震字幕の表示を有効または無効にします。

［最大震度2以下の地震情報を表示しない］
最大震度1または2などの地震情報を字幕対象外にします。

［津波情報］
津波字幕の表示を有効または無効にします。

［気象情報］
気象字幕を有効または無効にします。

［継続中の項目しかない電文を表示しない］
地域・種別などの表示フィルター適用後に残った項目がすべて「継続」の場合、字幕と音声を
実行しません。既定は有効です。新規発表・更新・解除は通常どおり表示されます。
継続情報だけでも毎回表示したい場合は、このチェックを外してください。

［火山情報］
火山字幕を有効または無効にします。

10.7 気象対象地域

「地域を選択」から複数の都道府県を選択できます。未選択は全国を意味します。
電文内の市町村等の警報コンテナを優先し、存在しない場合は二次細分区域、府県予報区
などの利用可能な階層を採用します。地域名に都道府県名が含まれる場合の重複表示を
避けます。

10.8 気象区分

・特別警報
・警報
・記録的短時間大雨情報
・気象防災速報
・竜巻注意情報
・その他の注意報

通常の注意報は、警報を埋もれさせないため既定で非表示です。竜巻注意情報は独立して
表示できます。非表示種別も受信ログと重複判定は継続します。

10.9 互換・安全

［/jma/quake/{id} 補完（7秒制限）］
P2P地震情報に不足項目がある場合、REST APIで補完します。通信待ちが表示を遅らせる
可能性があるため、7秒の上限を設けています。通常は無効です。

［本番中のテストを確認］
Production接続中の誤テストを防ぐ確認ダイアログです。Productionでは安全上、確認を
無効化できません。


11. 「表示・出力」タブ
----------------------------------------------------------------------

11.1 ページと文字

［ページ秒数］

・範囲   : 1.0～30.0秒
・単位   : 0.5秒
・既定値 : 4.0秒

複数ページを切り替える間隔です。

［ページ番号を表示］
複数ページ時に「1 / 3」のような番号を表示します。1ページだけの場合は表示しません。

［津波予報（0.2m／若干の海面変動）を表示］
有効にすると、津波警報・注意報に加えて津波予報も字幕へ含めます。既定は無効です。

［自動消去秒］

・EEW
・地震情報
・津波情報
・気象警報・注意報

既定値は各45秒です。0は自動消去しない設定です。継続状態を持つ津波や気象警報は、
解除または更新まで保持される場合があります。

11.2 本番情報の繰り返し表示

有効な最新情報だけを巡回表示します。

・新着情報は巡回より優先して即時表示
・更新報は旧報を置換
・取消、解除、期限切れは巡回対象外
・巡回間隔は1～300秒
・新着表示後の再開待ちは0～300秒
・地震、津波、気象、火山を個別設定
・繰り返し回数は1～100回
・音声は初回受信時だけが既定
・必要な分類だけ巡回ごとの音声再生を有効化可能

EEWは速報性と更新頻度のため本番巡回対象にしません。

11.3 キャンバス

・背景 : 透明、グリーン、ブルー
・既定解像度 : 1920×1080

OBS側でも位置、大きさ、切り抜きを調整できます。縦横比を不用意に変えると文字や
バッジが歪みます。

11.4 OBS Local View

［有効］
OBS向けローカルHTTP出力を有効にします。既定は有効です。

［ポート］
0では起動時に利用可能なポートを自動選択します。固定ポートを使う場合は、他のアプリ
と重複しない番号を指定してください。

［OBS更新間隔］

・範囲   : 50～1000ミリ秒
・既定値 : 1000ミリ秒

短いほど表示変更を早く通知しますが、CPU使用量とローカル通信量が増えます。

  1000ms     : 低負荷と安定性を優先
  250～500ms : 反応速度と負荷の均衡
  50～100ms  : 低遅延を優先。配信前に負荷確認が必要

この値はCDI-TelopperからOBSブラウザーソースまでの周期です。OBS描画、エンコード、
配信サービス、視聴者側プレーヤーの遅延は制御できません。

［15秒停止後にWS再同期］
ブラウザー側の更新が15秒以上停止した場合、OBS Local Viewの再同期を試みます。

11.5 OBS URLの一時トークン

URL末尾のtokenは、ローカル出力を不用意に閲覧されにくくするための一時値です。
起動ごとに変わります。ポート0ではポート番号も変わる可能性があります。


12. OBSへ手動登録する方法
----------------------------------------------------------------------

12.1 必要なソース

OBSへ次の4つのブラウザーソースを作成します。

・CDI-Telopper 地震字幕・全ての音声
・CDI-Telopper 緊急地震速報
・CDI-Telopper 津波字幕
・CDI-Telopper 気象情報

12.2 登録手順

1) CDI-Telopperを起動する
2) 左側の対象URLコピーボタンを押す
3) OBSで対象シーンを開く
4) ソースの「＋」から「ブラウザ」を追加する
5) 上記の分かりやすいソース名を付ける
6) 「ローカルファイル」を無効にする
7) URL欄へ貼り付ける
8) 幅1920、高さ1080を設定する
9) 「地震字幕・全ての音声」だけ「OBSで音声を制御する」を有効にする
10) 残り3ソースは音声を無効にする
11) 4ソースすべてを必要なシーンへ配置する

12.3 ブラウザーソース停止設定

常時受信する場合は、ソースが非表示になったときにブラウザーを停止する設定を避けて
ください。停止中に音声指示が発生すると、音声を取り逃す可能性があります。

12.4 URLが無効になった場合

アプリ再起動でtokenが変わり、ポート0ではポートも変わります。手動登録の場合は
4ソースへ最新URLを貼り直してください。毎回の貼り直しを避けるにはOBS WebSocket
自動登録を使用します。


13. OBS WebSocketで自動登録する方法
----------------------------------------------------------------------

13.1 OBS側の準備

OBS Studio 28以降ではOBS WebSocket 5.xが同梱されています。

1) OBSを起動する
2) 「ツール」から「WebSocketサーバー設定」を開く
3) WebSocketサーバーを有効にする
4) ポートを確認する（一般的には4455）
5) 認証を有効にする場合はパスワードを設定する
6) 設定を適用する

13.2 CDI-Telopper側

［OBSのブラウザーソースを自動作成・URL更新］
有効にすると、不足ソースを作成し、既存ソースのURLを現在の値へ更新します。

［OBS WebSocket URL］
既定値は次のとおりです。

  ws://127.0.0.1:4455

［パスワード］
OBS側のパスワードを入力します。Windows DPAPI CurrentUserで暗号化保存します。

［作成先シーン名］
空欄では同期時の現在プログラムシーンへ不足ソースを作成します。指定する場合はOBSの
シーン名と完全に一致させてください。

［今すぐOBSと同期］
現在の設定とURLを直ちに反映します。

13.3 自動同期の動作

・既存のCDI-TelopperソースがあればURLと1920×1080設定を更新
・不足ソースは指定シーンまたは現在シーンへ作成
・旧QTelopper字幕ソース名はCDI-Telopper名へ移行
・地震字幕・全ての音声だけを音声制御対象にする
・音声モニターは「モニターオフ」、つまりOBS出力のみ
・廃止済みのQTelopper/CDI-Telopper地震地図・津波地図ソースは削除
・OBSが停止中の場合は接続待ちとなり、一定時間後に再試行

13.4 音声ミキサー

OBS音声ミキサーに表示するのは「CDI-Telopper 地震字幕・全ての音声」だけです。
他の3ソースが過去設定によりミキサーへ表示される場合は、OBS同期を実行するか、
OBS側で音声制御を無効にしてください。


14. 「音声」タブ
----------------------------------------------------------------------

14.1 基本仕様

・対応形式 : WAV / MP3 / OGG
・音声ファイルは利用者が用意
・音源は配布物に同梱しない
・音声はOBSブラウザーソースへ100%で送信
・PCの既定スピーカーへアプリから直接再生しない
・音量はOBSミキサーで調整
・「保存して反映」で確定

音声ファイルは、アプリ更新時に消えない常設フォルダへ保存してください。USBメモリ、
一時フォルダ、ダウンロード後に移動予定の場所は避けてください。

14.2 共通設定

［ミュート］
すべての通知音を停止します。字幕は表示します。

［サンドボックス・訓練でも設定音声を使用］
有効にすると、試験・訓練表示でも本番用として設定した音源を使用します。

EEW音声は、地震・津波・気象の全音声より優先されます。EEW受信時は気象音声の
まとめ待ちを破棄し、再生中の対象音声をEEW音声で割り込みます。EEW音声が完了する
までに受信した地震・津波・気象音声は抑止し、完了後に遅れて再生することもありません。

14.3 地震情報

震度1、2、3、4、5弱、5強、6弱、6強、7を個別に有効化し、別々の音声を指定できます。
電文で観測された最大震度と一致する段階の音声を1回再生します。

14.4 津波情報

・津波予報（若干の海面変動）
・津波注意報
・津波警報
・大津波警報

各区分を個別に設定できます。1電文に複数区分がある場合は、最も高い区分の音声を
1回再生します。解除電文では再生しません。

14.5 気象警報・注意報

・レベル5（特別警報相当）
・レベル4～3（危険警報・警報相当）
・レベル2（注意報相当）

表示フィルター適用後の最も高い警戒レベルに対応する音声を再生します。解除情報では
再生しません。

気象防災速報（VPBS50/51）は、通常の気象警報・注意報とは別に有効・無効と音声ファイルを
設定できます。気象防災速報用の音声を無効にした場合、通常の気象警報用音声では代用しません。

同時受信まとめ時間は0～3秒、既定1.5秒です。短時間に分割して届いた気象電文を
まとめ、その中で最も高い音声だけを再生します。この待ち時間は気象だけに適用し、
EEW、地震、津波の音声は遅延させません。

14.6 緊急地震速報

・初報
・継続報
・取消報

それぞれ個別に音源と有効・無効を設定できます。同一イベントの更新関係を判定して
再生します。

14.7 OBS試聴

各音源の「OBS試聴」は、実際のOBS経路へテスト音声を送ります。安全のため本番接続中は
試聴できません。「OBS音声を停止」で現在の音声を停止できます。

14.8 音声が鳴らない場合

・音声ミュートを確認する
・対象段階のチェックとファイルパスを確認する
・ファイルが移動・削除されていないか確認する
・「保存して反映」を押したか確認する
・OBSで「地震字幕・全ての音声」が読み込まれているか確認する
・OBS音声ミキサーのミュート、フェーダー、配信トラックを確認する
・ログと診断情報の最後の音声結果を確認する


15. 「受信・過去電文を確認」ウインドウ
----------------------------------------------------------------------

15.1 開き方

・操作画面右上の「受信・過去電文を確認」
・タスクトレイ右クリックの「受信・過去電文を確認」

15.2 表示内容

左側に電文一覧を新しい順で表示し、右側に選択した電文の詳細と、生成された字幕を
ページ単位で表示します。

・情報種別
・受信元
・発表時刻、受信時刻
・電文型
・イベントID
・更新、取消、解除などの状態
・字幕ページ数
・各ページの本文

15.3 過去電文を取得

現在の履歴設定を使って過去電文を取得し、確認一覧へ追加します。確認するだけでは
OBS、音声、現在の字幕へ送出しません。

15.4 選択電文を再表示

選択した電文は、次の3方式から用途を選んで再表示します。「本番情報の再掲」では
識別バッジに電文の発表日時だけを表示し、「過去情報として紹介」と「動作訓練」では
用途と発表日時を表示します。

・本番情報の再掲
  本番で受信した電文を、視聴者への再周知として表示します。履歴元から取得した電文では
  選択できません。
・過去情報として紹介
  過去の災害や以前の発表内容を紹介する用途です。
・動作訓練
  表示・音声・配信手順の確認に使います。

再表示は通常の本番受信として重複キャッシュへ登録する処理とは分離されています。
発表日時は電文に記録された発表時刻を使い、現在と年が異なる場合は年も表示します。

15.5 操作画面を最小化した場合

確認ウインドウは操作画面の子画面として強制最小化されません。操作画面を最小化または
タスクトレイ格納しても、確認ウインドウは表示を維持します。


16. 履歴リハーサル
----------------------------------------------------------------------

16.1 取得元

［P2P地震情報（jma/quake）］
P2Pの地震情報APIから過去の地震情報を取得します。

［P2P履歴（地震・津波・EEW）］
P2P履歴APIから対応情報を取得します。

［気象庁防災情報XML DB（NII）］
国立情報学研究所の気象庁防災情報XMLデータベースから、利用者の手動操作時だけXMLを
取得します。ライブ受信には使用しません。

［外部JMA XMLファイル］
ローカルXMLファイルを1電文として読み込みます。最大2MiBです。

16.2 NII取得対象

・地震情報・津波情報
・地震情報のみ
・津波情報のみ
・気象注警報のみ（VPWW55～61）
・VPWW55～61の各分類
・地震・津波・気象注警報の全対応対象

検索日と取得対象を指定できます。NII個別電文URLを指定した場合は、その1件を優先します。
個別URLは許可されたNIIのHTTPS URLだけを受け付けます。

NII選択時は最大20件、ネットワーク要求間隔は1秒以上です。取得済みXMLはローカルへ
キャッシュし、同じ電文の不要な再取得を抑えます。

16.3 再生

・取得件数 : 1～100件（取得元ごとの上限が優先）
・再生間隔 : 秒単位で設定
・古い順に再生
・複数ページは全ページを1巡してから次の電文へ進む
・繰り返し再生を任意設定
・本番受信を検知すると履歴再生を停止

16.4 注意

履歴電文は過去の災害情報です。必ず訓練識別を確認し、本番情報と誤認しないようにして
ください。配信中に履歴を操作する場合は、本番中のテスト確認画面を確認してください。


17. 「テスト」タブと生データ・テストライブラリー
----------------------------------------------------------------------

17.1 収録シナリオ

主な収録対象は次のとおりです。

・緊急地震速報（警報、続報、取消）
・異なるイベントIDのEEW同時表示
・震度速報（ScalePrompt）
・震源・震度情報（DetailScale）
・遠地地震
・沖合の津波観測に関する情報（VTSE52）
・津波13地域
・津波解除
・大量地点、複数ページ
・気象警報・注意報
・火山警報、噴火速報
・南海トラフ地震臨時情報

「プレビューへ表示」でManualTestとして表示します。全ページに黄色の訓練バナーを
表示します。

17.2 生データ・テストライブラリー

次の形式を管理領域へコピーしてテストケース化できます。

・気象庁XML
・provider.xml
・transport.json
・DMDATA.JP生データ一式
・telegrams.jsonを含むDMDATA.JPアーカイブ
・任意の参考PNG
・対応形式をまとめたZIP

DMDATA.JP一式では、telegrams.jsonから収録XMLを1電文ずつ登録します。変換JSONは
参考資料として関連付けますが、字幕解析の正本には気象庁XMLを使用します。

安全でない相対パス、管理領域外参照、壊れたXML、XML正本のない項目、過大ファイルは
理由を表示して拒否します。

17.3 ライブラリー操作

・ファイルを登録
・DMDATA.JP一式を登録
・ZIPを取り込み
・選択実行
・複製
・ZIPを書き出し
・削除
・一括削除
・名前、分類、提供元、電文種別、イベントID、タグ、説明で検索

17.4 テスト実行の隔離

選択実行は訓練として扱います。本番履歴、通常の重複キャッシュ、本番電文の状態を
汚さないよう分離します。テスト結果は合否と理由を表示します。


18. 字幕、優先度、更新、取消、解除の処理
----------------------------------------------------------------------

18.1 共通処理

1) プロバイダー外枠を検証
2) JSONまたはXMLを安全に読み込む
3) 共通の災害イベントへ正規化
4) 分類別に選択された受信元か確認
5) 表示フィルターと地域を適用
6) イベントID、発表番号、内容署名で重複・更新関係を判定
7) ページを生成
8) 表示優先度を適用
9) OBS Local Viewへ送出
10) 条件を満たす音声を一般音声ソースへ送出

18.2 更新報

同じイベントの新しい報は古い報を置き換えます。古い報が遅れて到着した場合、表示を
巻き戻さないよう除外する場合があります。

18.3 取消報

取消報は対象イベントの表示を取消表示へ変更し、過去の震度、震源、対象地域などを
現在有効な情報のように残しません。

18.4 津波解除

警報・注意報の解除を検出すると、継続中の津波表示を解除表示へ切り替えます。
更新報では大津波警報、津波警報、津波注意報の区分を保持し、不要になった地域を
次の状態へ更新します。

18.5 気象の発表・継続・解除

市町村等の項目ごとに発表、継続、解除を保持します。同一イベントの複数電文は古い
状態を置き換えます。表示対象地域に発表中項目がなくなった場合は解除表示を生成します。

18.6 表示優先度

緊急性の高い情報は低い情報へ割り込みます。割り込まれた表示は、情報の種類と有効期限に
応じて再開、待機、置換、終了します。新着本番情報は履歴リハーサルや本番巡回より優先
します。

18.7 ページ分割

対象地域や地点が多い場合、読みやすい単位へ分割します。ページ番号表示が有効なら、
現在ページと総ページ数を表示します。字幕本文が過大にならないよう、文章と項目数の
両方を考慮して分割します。


19. ログ、生データ保存、診断情報
----------------------------------------------------------------------

19.1 画面ログ

画面上のログは最大250件です。最低レベルを選択し、コピーまたは表示クリアできます。
ログには接続、再接続、受信、表示対象外、認証、OBS、音声、履歴、設定移行などが
記録されます。

19.2 受信生データ保存

「受信したXML・JSONの生データを保存」は既定で無効です。有効にするとアプリデータ内の
raw-receptionへ保存します。

・既定保持日数 : 7日
・既定容量上限 : 256MB

生データには受信内容、イベントID、提供元情報などが含まれます。公開、共有、Git登録の
前に内容を確認してください。認証ヘッダーや保存済み資格情報は含めない設計ですが、
電文自体の取り扱い条件は提供元に従ってください。

19.3 診断情報保存

診断ZIPには、問題調査に必要な設定概要、ログ、稼働状態などを収録します。トークン、
APIキー、OBSパスワードなどの資格情報フィールドは伏字化します。

診断ZIPを第三者へ渡す前に、ファイル名、電文、パス、ログ、環境情報を利用者自身で
確認してください。

19.4 運用診断

本番前セルフチェック、設定プロファイル、異常監視・復旧通知、受信元比較の基盤を
備えています。診断結果や通知はOBS字幕・音声へ送出しません。画面上で非表示の機能は
開発・検証途中であり、一般運用手順には含めません。


20. 設定・状態・認証情報の保存とバックアップ
----------------------------------------------------------------------

20.1 既定保存先

旧版との互換性を保つため、製品名変更後も既定保存先識別子はQTelopperを維持します。

  %LOCALAPPDATA%\QTelopper\2.x-beta

主な保存内容は次のとおりです。

・settings.json        : 受信、表示、OBS、音声、履歴などの設定
・state.json等         : 表示状態、重複判定、再開用状態
・ログ                 : 実行ログ
・raw-reception        : 任意保存した受信生データ
・履歴キャッシュ       : 取得済みXML
・テストライブラリー   : 登録したテストケース

実際のファイル構成はバージョンにより増減します。

20.2 保存先の変更

開発・検証時は次の環境変数で2.x-betaの保存先を変更できます。

  QTELOPPER_V2_BETA_DATA_DIRECTORY

通常利用者は設定する必要はありません。存在しない場所、読み取り専用場所、共有フォルダを
指定すると起動や保存に失敗する可能性があります。

20.3 バックアップ

1) タスクトレイからCDI-Telopperを完全終了する
2) %LOCALAPPDATA%\QTelopper\2.x-betaを別の安全な場所へコピーする
3) バックアップに資格情報の暗号化データが含まれることを理解する
4) 公開ストレージへ置かない

20.4 復元とDPAPI

settings.json内のDMDATA.JP APIキー、AXISトークン、OBS WebSocketパスワードは、
保存したWindows利用者のDPAPIで暗号化されています。同じファイルを別PCや別利用者へ
コピーしても復号できません。移行先では資格情報を再入力してください。

20.5 設定破損時

settings.jsonやstate.jsonを直ちに削除せず、まず完全終了してバックアップし、別名へ
変更して起動確認してください。診断ZIPとログを保存してから初期化することを推奨します。


21. ネットワークとセキュリティ
----------------------------------------------------------------------

21.1 OBS Local View

OBS Local Viewは127.0.0.1のループバックへ限定して待ち受けます。外部PC向けWebサーバー
として使用しません。Host、Origin、一時tokenを検証し、HTMLへセキュリティヘッダーを
付与します。

21.2 XML

外部DTDと外部実体を拒否し、展開後サイズと入力サイズを制限します。テストZIPや
DMDATA.JPアーカイブでは、安全でない相対パスや管理領域外への展開を拒否します。

21.3 資格情報

・DMDATA.JP APIキー        : DPAPI CurrentUserで暗号化
・AXISアクセストークン     : DPAPI CurrentUserで暗号化
・OBS WebSocketパスワード  : DPAPI CurrentUserで暗号化
・診断ZIP                  : 資格情報フィールドを伏字化

画面共有中の入力、スクリーンショット、クリップボード履歴、外部バックアップについては
Windowsと利用者側の管理が必要です。

21.4 ファイアウォールとプロキシ

外部プロバイダーへのHTTPS/WSS通信を許可してください。企業・学校・配信スタジオなどの
プロキシ、TLS検査、DNS制限、VPNにより接続できない場合があります。OBS WebSocketは
同一PCのws://127.0.0.1を使用します。


22. 地図機能およびPC画面オーバーレイの廃止
----------------------------------------------------------------------

22.1 地図機能

地震地図と津波地図は完全廃止しました。

・地図URLはありません
・地図設定はありません
・地図用HTML/JavaScriptは配布物に含まれません
・地図画像、境界データ、Qmap素材は配布物に含まれません
・地図生成スクリプトは現行ソース公開対象に含めません
・地図専用テストは現行テスト対象に含めません
・旧OBS地図ソースはOBS自動同期時に削除します

地図が必要な場合は、利用者自身が権利と正確性を確認した別のOBSソースを使用して
ください。CDI-Telopperは地図の状態や整合性を管理しません。

22.2 PC画面オーバーレイ

デスクトップ上へ字幕を常時重ねる旧オーバーレイも廃止しました。PC上で確認するときは
「プレビューを表示」を使用します。受信内容の確認には「受信・過去電文を確認」を
使用します。


23. トラブルシューティング
----------------------------------------------------------------------

23.1 起動しない

・ZIP内から直接起動していないか確認する
・配布物をすべて展開する
・Windows 10/11 64ビットか確認する
・セキュリティソフトの履歴と隔離を確認する
・別フォルダへ再展開する
・診断用にsettings.jsonをバックアップして別名へ変更する

23.2 二重起動できない

仕様です。既存のCDI-Telopperを前面へ戻します。タスクトレイを確認してください。

23.3 「×」で終了しない

仕様です。受信継続のためタスクトレイへ格納されます。完全終了はタスクトレイの
「終了」を使用してください。

23.4 接続できない

・分類別受信元が「受信しない」だけになっていないか確認する
・インターネット接続、Windows時刻、DNSを確認する
・P2PのProduction/Sandboxを確認する
・DMDATA.JPのAPIキー、契約区分、同時接続枠を確認する
・DMDATA.JPのEEW契約が「警報」と「予報」のどちらかを確認する
・AXISトークン、有効期限、契約、チャンネルを確認する
・プロキシ、VPN、TLS検査、ファイアウォールを確認する
・ログの最初の認証・契約エラーを確認する

23.5 再接続時に終了する、再接続を繰り返す

最新版を使用し、診断ZIPとログを保存してください。手動切断後は自動再接続しません。
資格・契約エラーは待っても解消しないため、認証情報と契約を修正してください。

23.6 AXISトークンが更新されない

・期限まで7日以上ある場合は正常です
・確認は起動時と1日1回です
・すでに期限切れのトークンは更新できません
・有効なトークンをAXISで再発行して保存する
・API Base URLとネットワークを確認する
・ログにトークン値を書き込まないでください

23.7 受信しているのに表示されない

・分類別受信元が実際の提供元と一致しているか確認する
・表示フィルターを確認する
・気象の対象都道府県と警報レベルを確認する
・最大震度2以下の非表示を確認する
・対応外、選択外、重複、古い更新報、予報のみEEWではないか確認する
・受信結果とログを確認する

23.8 OBSに何も表示されない

・OBS Local Viewが有効か確認する
・OBS URLを最新値へ更新する
・4ソースの幅と高さを1920×1080にする
・ブラウザーソースを再読み込みする
・OBS WebSocket自動同期を実行する
・ソースの表示、シーン、重なり順を確認する
・テストシナリオで確認する

23.9 アプリ再起動後にOBS URLが使えない

tokenと自動ポートは起動ごとに変わります。OBS WebSocket自動登録を有効にするか、
4ソースへ新しいURLを貼り直してください。

23.10 OBS同期に失敗する

・OBSを先に起動する
・OBS WebSocketサーバーを有効にする
・ws://127.0.0.1:4455と実際のポートを一致させる
・パスワードを再入力する
・作成先シーン名を空欄にして現在シーンへ作成する
・OBS側に同名ソースが複数ないか確認する
・ログのObsBrowserSourceSyncを確認する

23.11 OBS音声ミキサーへ不要なソースが出る

「今すぐOBSと同期」を実行してください。音声対象は「地震字幕・全ての音声」だけです。
手動作成したEEW、津波、気象ソースでは「OBSで音声を制御する」を無効にしてください。

23.12 音が鳴らない

・ミュート、対象音声チェック、ファイルパスを確認する
・「保存して反映」を押す
・OBSで一般音声ソースが動作中か確認する
・OBSミキサーと配信トラックを確認する
・本番中はOBS試聴できないことに注意する
・診断ZIPの音声結果を確認する

23.13 音がPCスピーカーから鳴る

一般音声ソースの「OBSで音声を制御する」を有効にし、音声モニターを「モニターオフ」
にしてください。OBS自動同期でもこの状態へ設定します。

23.14 履歴取得に失敗する

・取得元と日付を確認する
・NII個別URLの形式を確認する
・取得件数を減らす
・連続操作を止め、時間を置く
・外部XMLが2MiB以下で正しいXMLか確認する
・ログのHistoryFetchFailedを確認する

23.15 DMDATA.JP一式を登録できない

・telegrams.jsonが存在するか確認する
・各項目に対応するXML正本があるか確認する
・相対パスに..や絶対パスが含まれていないか確認する
・ZIPやXMLが壊れていないか確認する
・表示された拒否理由を確認する

23.16 設定が保存されない

・「保存して反映」を押す
・範囲外入力がないか確認する
・保存先の書き込み権限と空き容量を確認する
・セキュリティソフトのブロックを確認する
・ログのSettingsエラーを確認する

23.17 設定を別PCへ移したら認証できない

仕様です。DPAPI暗号化値は別PCや別Windows利用者で復号できません。DMDATA.JP、AXIS、
OBS WebSocketの認証情報を移行先で再入力してください。

23.18 以前の地図ソースがOBSに残る

「今すぐOBSと同期」を実行してください。旧QTelopper/CDI-Telopperの地震地図・津波地図
ソースを検出して削除します。独自に同名を付けた別用途ソースがある場合は、同期前に
名前を変更してください。


24. 制限事項
----------------------------------------------------------------------

・本ソフト単独で情報の完全性、即時性、正確性、無停止を保証できません。
・受信プロバイダー、気象庁、インターネット回線の停止中は受信できません。
・切断中の速報を再接続後に完全復元できない場合があります。
・AXISは試験的プロバイダーであり、仕様や提供チャンネルが変更される可能性があります。
・DMDATA.JPとAXISは利用者の契約範囲外の電文を取得できません。
・表示フィルターを後から有効にしても、処理済みの同一報が再表示されない場合があります。
・OBSブラウザーソースが停止中の場合、音声指示を取り逃す可能性があります。
・低いOBS更新間隔でも配信プラットフォーム全体の遅延は短縮できません。
・音声ファイルの権利、保存、継続参照は利用者が管理します。
・地震地図、津波地図、地図素材、地図URLはありません。
・PCデスクトップへの常時字幕オーバーレイはありません。
・運用診断の一部は開発・検証中で、一般UIでは非表示です。
